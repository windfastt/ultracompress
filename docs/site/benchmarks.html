Scientific & Reproducible Methodology

How Every Number Is Collected & Verified

No cherry-picked flags, no unverified outputs, and no hidden lossy preprocessing. Every competitor is tested at both practical everyday settings and high-effort archival settings.

Reference Hardware & OS Manifest

  • CPU: AMD Ryzen 7 7800X3D (8 Cores / 16 Threads, Zen 4)
  • Memory: 64 GiB DDR5-6000 CL30 Dual-Channel
  • NVMe Storage: Samsung 990 PRO 2 TB PCIe 4.0 x4 NVMe
  • OS & Runtime: Windows 11 Pro 24H2 · .NET 8.0.11 x64 Release

Fairness & Measurement Rules

  • Bit-Exact Lossless Only: Every compressed archive is extracted to a clean directory and verified against the original input tree's SHA-256 manifest.
  • Multi-Thread Parity: Multi-threaded codecs (7za -mmt=16, zstd -T16, UltraCompress worker pool) are granted the same 16 logical threads.
  • OS Accounting: Peak RAM is captured via Windows Job Object PeakProcessMemoryUsed + child worker rollup; CPU seconds sum KernelTime + UserTime via GetProcessTimes.
  • Why CPU-sec / GiB Saved Matters: Divides total core-seconds consumed by net GiB saved — immediately exposing codecs that burn tens of thousands of CPU seconds on incompressible media for zero storage benefit.

Reproduce Locally from Source

Clone windfastt/ultracompress on Windows 10/11 with 7za, zstd, and brotli on PATH to regenerate JSON/CSV benchmark artifacts on your own hardware: 

# 1. Build solution in Release mode
dotnet build src/UltraCompress.sln -c Release

# 2. Run CI microbenchmark & harness verification
dotnet run -c Release --project tests/UltraCompress.Benchmarks -- --ci

# 3. Inspect machine-readable benchmark dataset backing this explorer
curl -sLO https://windfastt.github.io/ultracompress/data/benchmarks.json
